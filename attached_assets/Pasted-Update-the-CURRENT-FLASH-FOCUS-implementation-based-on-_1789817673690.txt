==================================================

The current game feels too fast.

The intended rhythm is:

SEE → PROCESS → DECIDE → RESPOND

not frantic clicking.

Use approximately:

EARLY GAME:
3.0-second response window.

MID GAME:
gradually reduce toward approximately 2.2 seconds.

FINAL DIFFICULTY:
gradually reduce toward approximately 1.7 seconds.

ABSOLUTE MINIMUM:
Never provide less than approximately 1.7 seconds for a normal round.

Difficulty progression must be gradual.

Do not suddenly jump between response times.

8. ROUND TRANSITION PACING
==================================================

CORRECT ANSWER:

- resolve once;
- show positive feedback;
- show score popup;
- wait approximately 250–300 ms;
- present next round.

Do not replace the word instantly on the same visual frame as the click.

INCORRECT ANSWER:

- resolve once;
- disable swatches immediately;
- briefly indicate the correct answer;
- show ONE humorous feedback message;
- keep it visible approximately 600–700 ms;
- remove it;
- start next round.

TIMEOUT:

- resolve once;
- show ONE humorous timeout/focus message;
- keep it visible approximately 600–700 ms;
- remove it;
- start next round.

9. FIX REPEATED / BLINKING FEEDBACK
==================================================

The current message:

“Quick reset — focus again.”

must NOT continuously blink, reappear or behave like a persistent status indicator.

Feedback must be EVENT-BASED.

A feedback message may appear only after:

- one incorrect answer; or
- one timeout.

Each resolved round may trigger a maximum of ONE feedback message.

Flow:

show message
→ remain visible 600–700 ms
→ fade once
→ remove completely
→ wait for another actual error event before showing another message.

Do NOT:

- use infinite CSS animation;
- repeatedly toggle visibility;
- trigger feedback from requestAnimationFrame;
- trigger feedback from timer updates;
- leave feedback permanently mounted and blinking;
- create overlapping feedback timers.

Use one controlled feedback state.

Clear any previous feedback timeout before creating another.
