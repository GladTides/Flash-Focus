Act as a senior product designer, UX writer, accessibility specialist, front-end engineer, and QA lead.

Your task is to improve the existing “Flash Focus” game landing page and onboarding experience to a production-quality 10/10 standard across visual design, brand identity, usability, onboarding, responsiveness, accessibility, performance, interaction design, and technical polish.

Do not replace the current design with a generic template. Preserve the established visual identity:

• Dark navy and charcoal interface
• Large editorial typography
• Warm orange primary accent
• Cyan secondary accent
• Monospaced technical labels
• “Borderless Arcade” positioning
• Premium cognitive-game aesthetic
• “Different signals. One clear decision.” as the primary tagline

Use the supplied screenshots and existing codebase as the source of truth. Inspect the full implementation before editing. Reuse the current design tokens, components, state management, APIs, and leaderboard logic where practical.

Do not invent backend capabilities that do not exist.

==================================================
1. PRIMARY PRODUCT GOAL
==================================================

Create a confident, polished, accessible landing experience that allows a first-time player to understand the purpose of Flash Focus, enter a name, review the rules, optionally practice, configure guidance settings, and begin the game without confusion.

The experience should feel like a premium micro-game rather than a corporate form, dashboard, or generic training module.

The interface must communicate:

1. What Flash Focus is
2. What the player must do
3. How long the game takes
4. What the main action is
5. How practice differs from the full game
6. That rules can change between rounds
7. That scores are for learning and entertainment, not an assessment of intelligence or job performance

==================================================
2. EXPERIENCE PRINCIPLES
==================================================

Use these principles to evaluate every decision:

• Clarity before decoration
• One obvious primary action per screen
• Progressive disclosure instead of instruction overload
• Concise, confident microcopy
• Strong visual hierarchy
• Consistent spacing and alignment
• Keyboard-first operability
• WCAG 2.2 AA accessibility
• Responsive behavior from small mobile screens to large desktop displays
• Motion that reinforces meaning
• Respect for reduced-motion preferences
• No manipulative, stressful, or misleading language
• No suggestion that results measure intelligence, capability, or employee performance

Do not claim a perfect score merely because the implementation is complete. Validate the work against the acceptance criteria at the end.

5. FIRST-TIME AND RETURNING-PLAYER FLOW
==================================================

Implement a coherent flow:

First-time player:
1. Enter first name or nickname
2. Select Start Game
3. Open Quick Briefing
4. Review controls and settings
5. Select “Got It · Let’s Go”
6. Begin the full challenge

Practice flow:
1. Enter first name or nickname if required by the implementation
2. Select “Practice Round · 5 Seconds”
3. Show only the minimum briefing required for practice
4. Begin the five-second sample
5. Show a clear completion state
6. Offer “Start Full Challenge” as the primary next action
7. Offer “Practice Again” as the secondary action

Returning player:
• Do not repeatedly force the full briefing unless required
• Keep a clearly discoverable “How to Play” action
• Allow the player to review or change audio and guidance settings
• Do not rely exclusively on local storage for essential functionality without graceful fallback

If the existing product requires a different sequence, preserve functional requirements while maintaining the same clarity.
