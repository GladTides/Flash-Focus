Modify the CURRENT FLASH FOCUS implementation based on hands-on gameplay testing.

Do not rebuild the game from scratch.

Do not change the leaderboard, scoring structure, 60-second session, Al-Futtaim / Borderless Thinking concept, Stroop mechanic, sound policy, or existing working features except where specifically instructed below.

The current game works, but hands-on testing identified two UX problems:

1. Gameplay becomes too fast and does not give the player enough time to consciously process the Stroop challenge.
2. Feedback such as “Quick reset — focus again.” keeps appearing/blinking repeatedly and becomes distracting.

Fix these issues carefully.

==================================================
1. UPDATE THE MAIN INSTRUCTION
==================================================

Replace:

“Tap the COLOR you see — not the word you read.”

with:

“Tap the COLOR you see — not the word you read. During BORDERLESS SHIFT, do the opposite.”

Use this exact wording consistently on the start screen and Help/instructions.

Do NOT use:
“and vice versa”

because the instruction should explicitly explain WHEN the opposite rule applies.

Keep the instruction visually prominent.

==================================================
2. SLOW THE GAME TO A CONTROLLED ARCADE PACE
==================================================

The current gameplay feels too fast.

The objective is NOT to make the game slow.

The objective is to create:

SEE → PROCESS → DECIDE → RESPOND

rather than frantic clicking.

Use approximately these answer windows:

EARLY GAME:
3.0 seconds maximum response time.

MID GAME:
gradually reduce toward approximately 2.2 seconds.

FINAL DIFFICULTY:
gradually reduce toward approximately 1.7 seconds.

ABSOLUTE MINIMUM:
Never give the player less than 1.7 seconds to answer a normal round.

Do not suddenly jump between response times.

Difficulty progression must be gradual.

The player should feel increasing pressure during the 60-second session without feeling that the interface is rushing uncontrollably.

==================================================
3. CONTROL ROUND TRANSITION SPEED
==================================================

After a CORRECT answer:

- show the positive response briefly;
- show the score popup;
- wait approximately 250–300 ms;
- then present the next round.

Do not instantly replace the word on the same visual frame as the click.

The player needs a tiny moment to register success.

After an INCORRECT answer:

- resolve the round once;
- show the correct answer clearly;
- show ONE humorous feedback message;
- keep the feedback visible for approximately 600–700 ms;
- then remove it completely;
- then start the next round.

After a TIMEOUT:

- resolve the round once;
- show ONE timeout/focus message;
- keep it visible approximately 600–700 ms;
- remove it completely;
- then start the next round.

==================================================
4. FIX THE BLINKING FEEDBACK BUG
==================================================

The message:

“Quick reset — focus again.”

currently appears to keep blinking/reappearing.

This must be fixed.

Feedback messages must be EVENT-BASED, not continuously rendered status messages.

A feedback message may appear ONLY when a specific round resolves as:

- incorrect; or
- timeout.

Each resolved round may trigger a maximum of ONE feedback message.

Once displayed:

1. show the message;
2. keep it visible for approximately 600–700 ms;
3. fade it out once;
4. remove it from the DOM or clear its state;
5. do not show it again until another incorrect answer or timeout occurs.

Do not use a repeating CSS animation.

Do not use an infinite animation.

Do not repeatedly toggle visibility.

Do not trigger feedback from the main animation loop.

Do not trigger feedback from every timer update.

Do not allow multiple feedback timers to overlap.

Before displaying new feedback, cancel/clear any previous feedback timeout.

Use a single controlled feedback state.
