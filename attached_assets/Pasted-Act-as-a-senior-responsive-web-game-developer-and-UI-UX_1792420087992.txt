Act as a senior responsive web-game developer and UI/UX engineer.

Perform a focused RESPONSIVE DESIGN PASS on the existing FLASH FOCUS standalone HTML.

PROJECT CONTEXT

FLASH FOCUS is an existing, working arcade game being prepared for an internal company AI competition.

The current desktop/laptop design is the visual source of truth.

The standalone version must remain:

standalone/index.html

and must remain a single self-contained HTML file.

IMPORTANT DESIGN PRINCIPLE

Do NOT attempt to fit the entire interface into one screen at every device size.

Use different responsive priorities for:

1. Laptop/Desktop Landing Page
2. Phone Landing Page
3. Active Gameplay

The correct behavior is:

LAPTOP / DESKTOP LANDING PAGE:
The important starting experience should fit comfortably without scrolling at common laptop resolutions.

PHONE LANDING PAGE:
Vertical scrolling is acceptable and expected. Preserve readability, spacing, hierarchy, and touch usability rather than shrinking everything to fit one screen.

ACTIVE GAMEPLAY:
The essential game interface should fit within one active viewport wherever reasonably possible, especially on laptop and typical modern phone screens. The player should not need to scroll while answering rounds.

Do not compromise the polished desktop design merely to force the mobile landing page into one viewport.

8. MOBILE GAMEPLAY LAYOUT
--------------------------------------------------

On narrow phones:

Use a compact game-specific layout rather than simply stacking the desktop game screen.

The main Stroop word must remain large and immediately readable.

Use responsive display typography, for example through `clamp()`, while maintaining sensible minimum and maximum sizes.

The word must never:

- overflow horizontally;
- become clipped;
- overlap controls;
- become too small to identify quickly.

The answer choices should use a touch-friendly responsive grid.

Depending on available width:

- 2 columns × 3 rows is acceptable for six choices;
- 3 columns × 2 rows may be used when sufficient width exists.

Choose whichever produces larger, clearer touch targets for the actual viewport.

Do not force six tiny buttons into one horizontal row on phone.

Each answer button must continue to show:

- gameplay color;
- readable color name.

Target approximately 44×44 CSS pixels or larger for touch controls wherever practical.

--------------------------------------------------
9. MOBILE VIEWPORT HEIGHT
--------------------------------------------------

Pay special attention to HEIGHT as well as width.

Flash Focus is a speed-based game, so a layout that technically fits horizontally but requires scrolling vertically during gameplay is not sufficient.

Use modern viewport units appropriately, including:

100dvh

where supported, with a reasonable fallback for browsers requiring traditional viewport units.

Account for mobile browser chrome and dynamically changing viewport height.

Do NOT globally lock the page to 100vh if doing so clips content.

Landing page:
natural vertical scrolling is allowed.

Gameplay:
prefer a game shell based on available dynamic viewport height.
